# OCR 캡처 (계획)

화면 영역의 글자를 텍스트로 뽑아 클립보드에 복사하는 기능. 아직 구현하지 않았다. 다른 PC에서 이어서 작업할 수 있도록 결정 사항과 순서를 적어 둔다.

## 왜 OCR인가 (클립보드 텍스트 기록은 하지 않기로 함)

- 클립보드 텍스트를 자동으로 모아 독에 넣는 안은 **버렸다.** 독의 항목은 사용자가 직접 캡처한 결과물이라는 규칙과 맞지 않고, 텍스트가 잦아서 스크린샷이 30개 상한에서 밀려나며, 비밀번호 같은 내용을 몰래 기록하는 구조가 캡처 앱의 신뢰와 어긋난다. 상시 감시는 전원 관리 부담도 있다.
- 대신 "화면의 글자를 뽑는다"는 캡처 앱답고, 캡처한 순간 한 번만 실행하므로 전원·프라이버시 부담이 없다. 온디바이스라 이미지가 밖으로 나가지 않는다.

## 동작

- 툴바에 "글자 복사" 단추를 추가한다(위치는 복사 앞이 자연스럽다. 최종 순서는 구현하면서 정한다).
- 영역(또는 창)을 고른 뒤 누르면 그 이미지를 OCR해서 텍스트를 클립보드에 복사하고, 썸네일 체크와 같은 방식으로 완료를 알린다.
- **독에 항목은 만들지 않는다.** 텍스트만 복사한다(독을 깔끔하게 유지). 항목으로 남길지는 쓰면서 다시 정한다.
- 글자를 못 찾으면 복사하지 않고 "글자를 찾지 못했어요"를 알린다.

## 구현

채널 `art.zoomon.snapdock/capture`에 메서드 `recognizeText`를 추가한다. 입력은 캡처한 영역(기존 캡처 경로 재사용), 출력은 문자열이다.

- **macOS**: Vision `VNRecognizeTextRequest`(`recognitionLevel = .accurate`, `recognitionLanguages`에 ko-KR, en-US 등). 구현은 `macos/Runner/CaptureChannel.swift` 옆에 `TextRecognizer.swift`로 둔다.
- **Windows**: `Windows.Media.Ocr.OcrEngine`(C++/WinRT, 이미 쓰는 Windows.Graphics.Capture와 같은 방식). `windows/runner/`에 `text_recognizer.cpp`를 두고 `capture_channel.cpp`에서 호출한다. 사용자 프로필 언어(`TryCreateFromUserProfileLanguages`)로 엔진을 만들고, 없으면 설치된 언어 중에서 고른다.
- Flutter 쪽은 `lib/capture/`에 채널 호출과 툴바 단추, 결과 알림만 추가한다. 문구는 l10n 파일에 넣는다.

## 알려진 한계

- Windows는 한국어 OCR이 **PC에 설치된 언어 팩**에 달려 있다. 팩이 없으면 한국어가 인식되지 않으므로, 이때는 "설정 > 시간 및 언어에서 한국어 팩을 설치하세요" 안내를 띄운다.
- 손글씨, 아주 작은 글자, 복잡한 배경은 정확도가 떨어진다. 세로쓰기와 표는 줄 순서가 어긋날 수 있다.
- 줄바꿈은 인식된 줄 단위로 유지한다.

## 작업 순서

1. Windows: `recognizeText` 구현 → 영역 선택 → 글자 복사 → 클립보드 확인.
2. Flutter 툴바 단추, 완료·실패 알림, l10n.
3. macOS: Vision 구현 후 같은 흐름 확인.
4. `CLAUDE.md`의 기능 범위·구현 현황에 반영하고 이 문서의 "계획" 표시를 지운다.

## 확인 목록

- [ ] 영어 문장, 한국어 문장, 섞인 문장이 맞게 복사된다.
- [ ] 원형 모드에서도 동작한다(바깥 투명 영역은 무시).
- [ ] 글자 없는 영역은 복사하지 않고 안내한다.
- [ ] 한국어 팩이 없는 Windows에서 안내가 뜬다.
- [ ] 배율이 다른 모니터에서도 인식 결과가 같다.
